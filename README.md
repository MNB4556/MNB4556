# I build to understand how things work

I like taking an idea apart until I understand the important layers, then
building a focused version with as few unnecessary dependencies as possible.
My projects tend to combine practical tools with questions I find interesting:
how light behaves, how to make a job search more manageable, and how to keep
useful history close to the person using it.

### Two tools for different parts of a job search

[career-ops](https://github.com/MNB4556/career-ops) helps find and track
opportunities. [Replay](https://github.com/MNB4556/job-search-replay) keeps a
history of what a listing said. Replay can import discovered postings from
career-ops' SQLite database in **read-only** mode, then manages its own
snapshots and timeline.

This is a one-time, user-initiated import—not live sync. Replay does not change
the career-ops database or import application statuses and private notes. Both
projects are local-first; Replay is explicitly a personal-use prototype, not a
hosted service.
